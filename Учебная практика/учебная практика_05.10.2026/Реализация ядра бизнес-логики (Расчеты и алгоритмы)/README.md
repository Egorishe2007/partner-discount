# Реализация ядра бизнес-логики (Расчеты и алгоритмы)

Задание: на бэкенде две независимые функции — расчет накопительной
скидки партнера и калькулятор расхода сырья для производства.

## 1. Алгоритм скидок

`calculate_partner_discount(total_quantity: int) -> int`
(`partner_discount.py`) — процент по общему количеству проданного
товара:

| Продано, шт. | Скидка |
| --- | --- |
| меньше 10 000 | 0 % |
| 10 000 – 49 999 | 5 % |
| 50 000 – 299 999 | 10 % |
| 300 000 и больше | 15 % |

Количество берется из базы (`partner_service.py`): запрос с `LEFT JOIN`
и `COALESCE(SUM(s.quantity), 0)` по `sales_history`. Партнер без продаж
получает 0 %, а не ошибку от `NULL`. `get_partner_discount(connection,
partner_id)` возвращает процент одного партнера, а для
несуществующего — `None`.

## 2. Алгоритм расчета материалов

`MaterialCalculator(catalog).calculate_material(product_type_id,
material_type_id, quantity, param_1, param_2) -> int`
(`material_calculator.py`):

```
Расход = ⌈ Количество × Параметр1 × Параметр2 × Коэффициент типа продукции
           × (1 + Процент брака / 100) ⌉
```

Считается в `Decimal`, а не во `float`: во `float` 100 × 1,1 =
110.00000000000001, и округление вверх выдало бы 111 вместо 110.
Округление — строго вверх, до целого (`ROUND_CEILING`).

## 3. Обработка ошибок

Метод получает `id` типа продукции и типа материала и запрашивает у
справочников базы коэффициент и процент брака:

```sql
SELECT coefficient FROM product_types WHERE id = %s
SELECT defect_percent FROM material_types WHERE id = %s
```

Справочники `product_types` и `material_types` появились в `schema.sql`
в этом задании, значения — из технического задания (ламинат 2,35,
массивная доска 5,15, паркетная доска 4,34, пробковое покрытие 1,50;
брак материалов 0,10–0,95 %).

Метод **возвращает `-1` вместо исключения**, если тип продукции или
материала не найден в справочнике, если параметры не больше нуля или
не числа, если количество не целое или не больше нуля. Нецелый `id` в
базу даже не отправляется. Метод `find_problem` с теми же проверками
объясняет причину текстом — для сообщения пользователю в интерфейсе.

## 4. Оформление

Стиль — `snake_case` для функций и переменных, `CamelCase` для классов,
строго одна команда на строку. Это проверяет тест `test_code_style.py`
по всем модулям папки, в том числе `etl.py` из прошлого задания: он
разбирает код через `ast` и ищет строки, где начинается больше одной
команды, точки с запятой и имена не в выбранном стиле.

## Проверка на настоящей базе

База собрана из этой папки (`schema.sql`, `import.sql` с данными
заказчика из прошлого задания) на PostgreSQL 18.4. Вывод
`python core_demo.py`:

```
Скидки партнеров:
  ООО Альфа          продано  10 шт. -> 0 %
  ООО Вектор         продано   2 шт. -> 0 %
  ИП Петров А.В.     продано   1 шт. -> 0 %
  ИП Сидоров И.И.    продано   1 шт. -> 0 %
  АО Технолоджис     продано   3 шт. -> 0 %
  партнер 999: None
Расчет материалов (тип прод., тип мат., кол-во, п1, п2):
  (1, 1, 250, 2.5, 1.2) -> 1765
  (3, 2, 100, 1.5, 0.8) -> 526
  (4, 5, 40, 3.0, 2.0) -> 362
  (99, 1, 250, 2.5, 1.2) -> -1
  (1, 0, 250, 2.5, 1.2) -> -1
  (1, 1, 250, -2.5, 1.2) -> -1
  (1, 1, 0, 2.5, 1.2) -> -1
```

У всех партнеров заказчика продажи меньше 10 000 штук, поэтому скидка
везде 0 %. Границы 5, 10 и 15 % проверяют unit-тесты. Расчет
сырья: ламинат, тип материала 1, 250 шт., 2,5 × 1,2 → 2,5 × 1,2 × 2,35 ×
250 × 1,001 = 1764,2625 → **1765**. Дальше по одному случаю на каждую
ошибку: несуществующий тип продукции, несуществующий тип материала,
отрицательный параметр, нулевое количество.

## Файлы

| Файл | Назначение |
| --- | --- |
| `partner_discount.py` | алгоритм скидки |
| `partner_service.py` | объем продаж, данные партнера и история из базы |
| `material_calculator.py` | метод расчета материалов, справочники из базы и в памяти |
| `db.py` | подключение к PostgreSQL, пароль из `DB_PASSWORD` |
| `core_demo.py` | консольная проверка ядра на базе |
| `schema.sql` | таблицы, в том числе новые справочники для расчета |
| `etl.py`, `import.sql`, `import_check.sql`, `data/` | очистка и импорт данных из прошлого задания |
| `test_partner_discount.py` | границы скидок |
| `test_partner_service.py` | запросы на поддельном соединении |
| `test_database.py` | ядро на настоящей базе; без базы пропускается |
| `test_code_style.py` | одна команда на строку и стиль имен |
| `test_etl.py` | очистка данных |

## Запуск

```
pip install -r requirements.txt
psql -U postgres -c "CREATE DATABASE partners_db"
psql -U postgres -d partners_db -f schema.sql
psql -U postgres -d partners_db -f import.sql
python core_demo.py
```

`import.sql` берет уже очищенные `data/clean_*.csv`. Если сырые файлы
поменялись, сначала `python etl.py`.

python -m unittest -v

история через `JOIN`, расчет сырья по справочникам и `-1` для
