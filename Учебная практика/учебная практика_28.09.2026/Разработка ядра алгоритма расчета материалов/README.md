# Разработка ядра алгоритма расчета материалов

Задание: метод, который точно считает сырье для производства по
параметрам изделия, коэффициенту типа продукции и проценту брака
материала, без ручных ошибок менеджеров.

## Метод

```python
MaterialCalculator(catalog).calculate_material(
    product_type_id, material_type_id, quantity, param_1, param_2) -> int
```

Пять входных параметров из ТЗ: `product_type_id` и `material_type_id`
(int), `quantity` — количество продукции (int), `param_1` и `param_2` —
положительные вещественные параметры продукции. Справочники передаются
один раз в конструктор, поэтому сигнатура самого метода остается ровно
такой, как в задании.

## Логика расчета

1. Базовый расход на 1 ед. = `param_1 × param_2 × коэффициент типа
   продукции`.
2. Общий чистый расход = базовый расход × `quantity`.
3. Итог с учетом брака = чистый расход × `(1 + процент брака / 100)`.
4. Результат округляется до целого в большую сторону.

Пример из демонстрации: ламинат (коэффициент 2,35), тип материала 1
(брак 0,10 %), 250 штук, параметры 2,5 и 1,2:
2,5 × 1,2 × 2,35 = 7,05 → 7,05 × 250 = 1762,5 → 1762,5 × 1,001 =
1764,2625 → **1765**.

**Считаем в `Decimal`, а не во `float`.** Во `float` 100 × (1 + 10 / 100)
= 110.00000000000001, и округление вверх дало бы 111 вместо 110 — лишняя
единица сырья на ровном месте. `Decimal` хранит десятичные дроби точно;
числа переводятся в него через строку (`Decimal("2.35")`), иначе в него
попала бы та же двоичная погрешность.

## Справочники

Коэффициент типа продукции и процент брака метод берет из справочника,
который передан в `MaterialCalculator`:

- `DatabaseCatalog` — таблицы `product_types` и `material_types` в
  PostgreSQL, запрос по `id` с параметром:
  `SELECT coefficient FROM product_types WHERE id = %s`;
- `MemoryCatalog` — мок-объект: те же значения в словарях, для проверки
  метода без базы данных.

Таблица `material_types` появилась в `schema.sql` в этом задании:
пять типов материала с процентом брака 0,10; 0,95; 0,28; 0,55 и 0,34.
Коэффициенты типов продукции — 2,35; 5,15; 4,34 и 1,50.

## Обработка ошибок

Метод возвращает `-1` вместо исключения, если:

- тип продукции или тип материала не найден в справочнике — в том числе
  если id вообще не целое число (такой id в базу даже не отправляется);
- `param_1` или `param_2` меньше или равен нулю: по ТЗ параметры
  положительные, поэтому ноль тоже ошибка; не число, `NaN` и
  бесконечность — тоже;
- `quantity` меньше или равно нулю либо не целое число.

Рядом с методом есть `find_problem` с теми же проверками: он объясняет
текстом, почему расчет вернул `-1`, и подсказывает, что исправить. Это
пригодится окну расчета в следующем задании. Недоступная база — не
ошибка входных данных, поэтому в этом случае метод не прячет исключение
за `-1`: его покажет окно.

## Запуск

```
pip install -r requirements.txt
psql -U postgres -d partners_db -f schema.sql
python material_demo.py
```

Без базы данных — те же справочники в памяти:

```
python material_demo.py --mock
```
