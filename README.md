# Расчет скидки партнера

Учебный проект: ядро бизнес-логики (индивидуальный процент скидки партнера),
получение объемов продаж из базы данных и экранная форма для менеджера.

Python 3.10, PostgreSQL 18, драйвер psycopg2, интерфейс на Tkinter.

![Окно приложения](docs/screenshot.png)

## Задание 1. Ядро бизнес-логики (расчет скидки)

Критерии расчета из ТЗ:

| Суммарный объем продукции | Скидка |
| --- | --- |
| менее 10 000 ед. | 0 % |
| от 10 000 до 49 999 ед. | 5 % |
| от 50 000 до 299 999 ед. | 10 % |
| от 300 000 ед. и более | 15 % |

Отрицательный объем считается ошибкой ввода: функция выдает `ValueError`.

Запуск тестов:

```
python -m unittest -v
```

Проверяются границы 0, 9999, 10000, 49999, 50000, 299999, 300000 и
отрицательное значение. Всего в проекте 13 тестов.

Покрытие тестами функции расчета:

```
pip install coverage
python -m coverage run --branch -m unittest
python -m coverage report -m
```

## Задание 2. Интеграция с БД и агрегация данных

Подготовка базы данных:

```
psql -U postgres -c "CREATE DATABASE partners_db"
psql -U postgres -d partners_db -f schema.sql
```

Параметры подключения берутся из переменных окружения, пароль в коде не
хранится:

| Переменная | Значение по умолчанию |
| --- | --- |
| `DB_HOST` | `localhost` |
| `DB_PORT` | `5432` |
| `DB_NAME` | `partners_db` |
| `DB_USER` | `postgres` |
| `DB_PASSWORD` | не задан, берется стандартная `PGPASSWORD` |

Установка драйвера и консольная проверка:

```
pip install -r requirements.txt
python main.py
```

## Задание 3. Разработка интерфейса по руководству по стилю

Экранная форма на Tkinter, оформление вынесено в `ui_style.py`.

- Заголовок окна — «CRM: Список партнеров и скидок».
- Иконка приложения в углу окна — `resources/icon.ico`.
- Логотип компании в шапке формы — `resources/logo.png`.
- Главный макет — список карточек партнеров по руководству по стилю:
  «Тип | Наименование партнера», директор, телефон, рейтинг, а справа —
  процент скидки. Белый фон, тонкая серая рамка, шрифт Segoe UI.

Запуск:

```
python app.py
```

## Задание 4. Наполнение интерфейса и отладка

- Карточки заполняются данными из БД функцией `get_partners_with_discounts`:
  один запрос с `LEFT JOIN` и `SUM(quantity)` по всем партнерам, скидка
  считается функцией из задания 1.
- Если истории продаж нет, `SUM(quantity)` дает `NULL`; объем приводится к 0,
  скидка показывается как 0 %, `TypeError` не возникает.
- Если база недоступна, окно открывается и пишет причину в строке состояния,
  приложение не падает.
- Кнопка «Обновить» перечитывает данные из базы.

Проверка без реальной базы — `test_partner_service.py`: партнер с продажами,
партнер с пустой историей (`NULL`), нулевой объем, несуществующий партнер и
список партнеров целиком.
